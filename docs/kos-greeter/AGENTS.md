# 本目录代理规范

本目录是 KOS Greeter 研究与任务包。用户要求只研究的历史范围仍是本包基线；后续实施须由新的明确任务授权，文档本身不授权部署。

1. 先读 README、research、constraints、acceptance 和被指派任务卡。
2. 修改本包时只操作本目录，不改登录管理器配置、PAM、系统服务或项目实现。
3. 用户明确授权某张实施卡后按其范围工作；系统切换不是普通 UI 原型的附带步骤。
4. 使用源码/官方资料标注事实、建议、未知，核验版本与来源。概念视觉必须保留示意标识。
5. 任务卡状态初始为“待开始”；没有运行证据不得改为通过。
6. 凭据不进代码、日志、环境描述、截图或文档。第三方 QML 不在登录前运行。
7. 附上验收证据模板；失败必须记录恢复方法和最终系统状态。
8. `agent.md` 只是本文件入口，没有第二套规则；发生冲突时以用户指令及上级有效规范优先。

## 每次完成后的独立子代理审查

这是用户明确要求的完成门槛，适用于本包文档变更及按本包派发的全部 Greeter 研究、实现和验收任务，即使实施文件位于本目录之外。

- 每次完成一个任务或一批明确界定的变更后，执行者必须调用独立子代理审查当前产物；没有独立审查不能报告任务完成或将任务卡关闭。
- 审查代理不得参与被审任务的编写或实现。执行者自查、重新读取文件、自动测试及原作者自审均不能替代独立审查。
- 审查须覆盖最终版本、相关上下游约束和验收证据。提交明确的问题、优先级、位置、理由、修复建议及结论。
- 发现问题后由执行者修复，再交给独立审查代理复审。审查代理保持只读；修复后不能仅凭执行者自查关闭问题。
- P0/P1/P2 问题关闭后才能标记完成；P3 可记录原因和后续处理，但须经审查确认不阻断本次目标。
- 保存审查记录、被审版本或文件摘要、问题处置和复审结论。审查结论之后若产物再次变化，变化部分及受影响的依赖必须再审。
- 无法调用独立子代理时标记“待独立审查”，说明缺失项，不能把自查当作通过。

完整流程、状态和记录字段见 [独立审查规则](REVIEW_POLICY.md)。独立审查本身不递归要求再创建审查代理；它是执行任务的完成检查，不能借此形成无限调用。
