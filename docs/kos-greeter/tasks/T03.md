# T03 展示资源发布与权限

状态：完成（隔离发布侧）。负责人：Codex。阶段：用户明确指派 T03，隔离发布侧实现及验证。

## 目标

制定并验证KOS背景副本与manifest发布。

## 依赖与开始条件

T01。依赖交付物须可复查；失败或未测不能冒充满足。

## 范围

有限展示资源，不执行用户代码。

## 具体步骤

1. 审查允许路径/所有权。
2. 实现原子版本发布方案。
3. 校验hash/尺寸。
4. 注入缺图/损坏/过期。
5. 评审头像副本。

## 交付物

发布契约、权限表、故障用例。记录提交、组件版本和证据相对路径。

## 验收

A03-P/A18 及本卡资源发布范围的 A11/A13，无 home 权限放宽。完整三阶段 A03 留到 T14；不得将本卡通过写成端到端 A03 通过。按 [验收矩阵](../acceptance.md) 与 [证据模板](../evidence/TEMPLATE.md)逐项填写。未测保留未测；证据缺失不得关闭任务。

## 失败回退

内置背景与默认头像。记录触发条件、恢复命令/操作、耗时与最终状态；失败场景必须可重复。

## 非目标

同步完整用户配置或密码。不扩大认证权限、不顺带重构无关模块。

## 约束与评审

遵守 [硬约束](../constraints.md) 与 [AGENTS.md](../AGENTS.md)。存在证据冲突时暂停依赖动作，先澄清事实；普通原型不授权系统服务切换。

## 执行细化

输入入口是 WallpaperService 的实际mode/fit/resource，而非Plasma背景。发布提案应说明请求者UID、资源读取进程与最终文件所有者，采用临时文件→内容校验→原子rename，避免Greeter读半张图片。资源目录不能同时允许普通用户写入可执行QML。

manifest仅保存所需展示字段；图片先探测尺寸/格式并设置解码预算，hash用于防止新旧资源串用。提交点前发布失败不能覆盖上一份有效manifest；提交点后异常按发布契约通过 consume/recover 确认状态并继续清理。删除源图、移走外盘、home未解密、写入中断与版本升级分别注入；确认Greeter只读取发布副本，损坏时稳定默认背景。收集权限/所有权清单和拒绝路径样例，日志不记录密码。

## 完成后的独立子代理审查

每次完成本卡工作，先标记待独立审查，必须调用未参与本卡编写或实现的独立子代理审查当前产物、相关约束和验收证据。执行者修复后交独立代理复审；P0/P1/P2关闭后才能标记完成，P3须记录处置并经审查确认。保存被审版本、代理ID、问题及复审结论。不得用作者自查替代。详见 [独立审查规则](../REVIEW_POLICY.md)，填写 [证据模板](../evidence/TEMPLATE.md)。

发布前须有每账户明确的“同步至登录界面”选择，并告知资源会在认证前向其他使用者展示；桌面选图不自动等于公开授权。关闭同步、撤销图片或删除账户时，撤销 manifest 引用并清理登录端缓存、快照及旧版本副本；正在使用的旧资源按引用生命周期清理，不能永久遗留。测试拒绝同步、切换图片后旧版本清理、撤销后重新加载、账户删除及清理中断恢复；未授权/已撤销资源回退内置背景。
