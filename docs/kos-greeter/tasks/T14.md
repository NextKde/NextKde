# T14 故障矩阵与集成评审

状态：阻断（隔离测试/集成评审包及独立审查通过；完整验收缺证据）。负责人：Codex 主代理。阶段：测试与方案评审；未执行部署。

2026-10-12交付：[验收报告](../evidence/T14/REPORT.md)、[集成/恢复方案与风险表](../evidence/T14/INTEGRATION.md)、[复现入口](../evidence/T14/run.py)。完整T11–T13依赖、实机故障恢复及A18/A19仍缺证据，不能关闭本卡。

## 目标

完整故障恢复后形成可批准集成包。

## 依赖与开始条件

T05,T06,T09,T10,T11,T12,T13。依赖交付物须可复查；失败或未测不能冒充满足。

## 范围

测试与方案评审，部署单独授权。

## 具体步骤

1. 执行验收组合。
2. 敏感数据审查。
3. 备份/恢复演练。
4. 核验原管理器可恢复。
5. 列剩余缺口。
6. 准备安装卸载和升级方案。

## 交付物

验收报告、风险表、集成/恢复方案。记录提交、组件版本和证据相对路径。

## 验收

G0–G4，所有严重阻断消除。按 [验收矩阵](../acceptance.md) 与 [证据模板](../evidence/TEMPLATE.md)逐项填写。未测保留未测；证据缺失不得关闭任务。

## 失败回退

停止集成，回到原管理器和安全桌面。记录触发条件、恢复命令/操作、耗时与最终状态；失败场景必须可重复。

## 非目标

未经明确授权直接替换实机服务。不扩大认证权限、不顺带重构无关模块。

## 约束与评审

遵守 [硬约束](../constraints.md) 与 [AGENTS.md](../AGENTS.md)。存在证据冲突时暂停依赖动作，先澄清事实；普通原型不授权系统服务切换。

## 执行细化

从acceptance矩阵逐项分配证据文件，不只做正常密码成功场景。至少演练home不可读、图片失效、认证取消、greeter崩溃、user session立即退出、Cover超时、Shell崩溃和显示拔线。每项记录恢复操作与最终活跃会话/服务状态。

准备安装/卸载草案：文件清单、版本依赖、原管理器备份、单次试运行方式、持久启用方式和恢复命令分开列。当前任务只有评审，不执行本机持久切换。明确系统服务变更所需用户授权，不把研究文档当授权。

评审包包括严重阻断清单、未测项、隐私检查、资源分发许可、真实录像和性能限制。G0–G4都满足后才建议用户评审G5；仍有零黑帧/原版参数缺口时应声明首版范围，而不是隐藏在通过列表。

## 完成后的独立子代理审查

每次完成本卡工作，先标记待独立审查，必须调用未参与本卡编写或实现的独立子代理审查当前产物、相关约束和验收证据。执行者修复后交独立代理复审；P0/P1/P2关闭后才能标记完成，P3须记录处置并经审查确认。保存被审版本、代理ID、问题及复审结论。不得用作者自查替代。详见 [独立审查规则](../REVIEW_POLICY.md)，填写 [证据模板](../evidence/TEMPLATE.md)。

集成验收覆盖 A18 同步可见范围、撤销、旧版本垃圾回收和账户删除。验证同 UID 多图形会话受支持范围；当前共享服务限制未解除时明确拒绝不支持的第二会话，不得以 T09 文件级隔离测试宣称完整并发支持。

按 A19 交付并验证独立 app 的专属安装/卸载/升级恢复入口。资源安装与持久启用分离，覆盖干净环境、缺依赖、重复安装、升级失败回滚及合集不启用 Greeter；参照 [App 安装方案](../app-packaging.md)。当前仅更新设计，不执行安装或系统切换。
