# T13 交接性能与黑帧测量

状态：阻断（测量准备实现/验证及独立审查通过；完整 A16 未测）。负责人：主代理。用户已授权本卡实施（2026-10-12）。

测量工具与规范见 [执行记录](../evidence/T13/REPORT.md) 和 [采集规范](../evidence/T13/PROTOCOL.md)。真实原始录像及 T11 完整依赖仍缺失，不能关闭任务。

## 目标

量化跨合成器空白与视觉跳变。

## 依赖与开始条件

T06,T11。依赖交付物须可复查；失败或未测不能冒充满足。

## 范围

高帧率录像、帧时间线、多配置对照。

## 具体步骤

1. 定义空白帧。
2. 记录cold/warm/logout。
3. 240/60Hz比较。
4. 对齐时钟。
5. 区分无信号/黑色内容。
6. 归因DRM链路。

## 交付物

原始录像、统计表、性能结论。记录提交、组件版本和证据相对路径。

## 验收

A16，有采样率与误差，不把未测作零。按 [验收矩阵](../acceptance.md) 与 [证据模板](../evidence/TEMPLATE.md)逐项填写。未测保留未测；证据缺失不得关闭任务。

## 失败回退

降低声明并保留基础衔接。记录触发条件、恢复命令/操作、耗时与最终状态；失败场景必须可重复。

## 非目标

用单截图证明零黑帧。不扩大认证权限、不顺带重构无关模块。

## 约束与评审

遵守 [硬约束](../constraints.md) 与 [AGENTS.md](../AGENTS.md)。存在证据冲突时暂停依赖动作，先澄清事实；普通原型不授权系统服务切换。

## 执行细化

先定义空白类别：显示无信号、纯黑内容、错误占位、冻结旧帧分别统计，不能合并成“流畅”。外部录像帧率/曝光/采样时长需记录；高刷新屏的录像采样不足必须报告测量上限。录制前清除密码可见区域，只拍真实认证成功后的交接。

每种模式重复冷启动、注销返回和热启动样本，记录认证完成、退场完成、旧KWin释放、新KWin连接、Cover首帧、桌面揭幕。跨进程monotonic事件对齐，不把frameSwapped称为scanout。统计最大值、中位数、样本数与异常，保存原始视频及抽帧索引。

对比60与239.998Hz、相同/不同mode，以及动态静态回退。只有数据支持时才建立零黑帧专项改进提案；不得为了动画去修改DRM内核或KWin核心而不单独评审。

每次完成本卡工作，先标记待独立审查，必须调用未参与本卡编写或实现的独立子代理审查当前产物、相关约束和验收证据。执行者修复后交独立代理复审；P0/P1/P2关闭后才能标记完成，P3须记录处置并经审查确认。保存被审版本、代理ID、问题及复审结论。不得用作者自查替代。详见 [独立审查规则](../REVIEW_POLICY.md)，填写 [证据模板](../evidence/TEMPLATE.md)。
