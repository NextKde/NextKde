## 非目标

## 约束与评审

遵守 [硬约束](../constraints.md) 与 [AGENTS.md](../AGENTS.md)。存在证据冲突时暂停依赖动作，先澄清事实；普通原型不授权系统服务切换。

## 执行细化

入口为系统bus AccountsService，只读取得UID/UserName/RealName/IconFile，UID用于配置关联；显示名改变不改变登录身份。缓存列表缺少账户时保留手工用户名入口，并测试不存在用户、空RealName、坏头像和不可读home。认证UI不要假定只有一次密码提示，应根据greetd提示显示secret或普通输入、等待与取消。用可访问键盘导航选择用户和回到列表；失败日志只保存非敏感状态。以两账户和Other user路径录制证据。

## 完成后的独立子代理审查

每次完成本卡工作，先标记待独立审查，必须调用未参与本卡编写或实现的独立子代理审查当前产物、相关约束和验收证据。执行者修复后交独立代理复审；P0/P1/P2关闭后才能标记完成，P3须记录处置并经审查确认。保存被审版本、代理ID、问题及复审结论。不得用作者自查替代。详见 [独立审查规则](../REVIEW_POLICY.md)，填写 [证据模板](../evidence/TEMPLATE.md)。

认证提示必须按实际 Quickshell Greetd API 区分 authMessage 的提示类型与 authFailure：authMessage.error 不直接推导为认证会话终止；仅 responseRequired 时提交响应，echoResponse 决定可见输入或隐藏输入。authFailure 后清空凭据并重建会话；覆盖信息提示、可恢复错误提示、多轮响应及最终失败。
