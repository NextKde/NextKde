# T10 早期桌面Cover

状态：完成（实现/隔离 A09/A14-C 及独立复审通过）。负责人：Codex。阶段：用户明确授权实现（2026-10-12）。

实现与隔离验收见 [Cover 契约](../contracts/early-cover.md)和[证据](../evidence/T10/REPORT.md)。

## 目标

用户KWin可连接后尽早显示相同背景。

## 依赖与开始条件

T07,T09。依赖交付物须可复查；失败或未测不能冒充满足。

## 范围

轻量进程、输出覆盖、超时撤罩。

## 具体步骤

1. 设计不依赖platform/data的启动顺序。
2. 验证层级。
3. 映射记录。
4. Shell延迟/崩溃。
5. 退出路径与快捷键恢复。

## 交付物

服务顺序方案、Cover原型、帧与故障证据。记录提交、组件版本和证据相对路径。

## 验收

A09/A14-C，不永久挡桌面；本卡用可控就绪/失败信号模拟 Shell，真实 Shell 集成及完整 A14 留 T11/T14。按 [验收矩阵](../acceptance.md) 与 [证据模板](../evidence/TEMPLATE.md)逐项填写。未测保留未测；证据缺失不得关闭任务。

## 失败回退

受控撤罩与诊断，必要时恢复TTY。记录触发条件、恢复命令/操作、耗时与最终状态；失败场景必须可重复。

## 非目标

覆盖KWin接管前空白。不扩大认证权限、不顺带重构无关模块。

## 约束与评审

遵守 [硬约束](../constraints.md) 与 [AGENTS.md](../AGENTS.md)。存在证据冲突时暂停依赖动作，先澄清事实；普通原型不授权系统服务切换。

## 执行细化

启动入口置于用户会话引导阶段；等待KWin socket实际可连接，再运行独立Cover，与Plasma/KOS并行。不能把After=kos-platform或完整Shell就绪作为Cover开始条件。检查输出发现和窗口创建不依赖用户平台RPC。

每输出创建覆盖背景窗口并记录ResourceReady、WindowMapped、FrameSubmitted；如支持presentation反馈则另记FramePresented。Cover层级需遮住初始化闪现，同时避免锁住恢复通道。其自有超时与退出监听不依赖被遮盖的Shell进程。

故障注入：无资源、一个输出不ready、Shell永不ready、Cover自身崩溃、输出热拔和KWin重启。失败时撤罩或切固定诊断并保留TTY恢复，不无限遮挡。录像标明Cover第一帧出现之前的空白，不宣称已覆盖DRM交接。

## 完成后的独立子代理审查

每次完成本卡工作，先标记待独立审查，必须调用未参与本卡编写或实现的独立子代理审查当前产物、相关约束和验收证据。执行者修复后交独立代理复审；P0/P1/P2关闭后才能标记完成，P3须记录处置并经审查确认。保存被审版本、代理ID、问题及复审结论。不得用作者自查替代。详见 [独立审查规则](../REVIEW_POLICY.md)，填写 [证据模板](../evidence/TEMPLATE.md)。
