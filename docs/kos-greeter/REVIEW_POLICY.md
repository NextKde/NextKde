# 每次任务完成后的独立子代理审查规则

本规则来自用户要求，适用于本包维护和依照本包开展的 Greeter 工作。它要求每个任务交付经过独立审查，不表示文档审查替代真实认证、显示交接或恢复验收。

## 完成流程

1. 执行者完成任务范围内的工作，运行与变更相称的检查，整理待验收项。
2. 将任务标为“待独立审查”，冻结本次被审范围：提交 ID，或未提交文件的路径与 SHA256 清单。不要先标为完成再补审。
3. 调用没有参与该范围编写或实现的独立子代理，提供目标、文件、依赖、约束、证据、未测项及被审版本。
4. 审查代理只读检查，返回问题与结论。测试结果、文件存在或作者自查不能替代此步。
5. 执行者修复问题，记录变更和验证；原独立审查代理或另一合格独立代理复审修复后的版本。
6. 所有 P0/P1/P2 问题关闭；P3 的延后理由经审查确认不阻断目标；按任务要求验收通过后，才可标记“完成”。

研究或文档任务允许将未来硬件验证列为明确交付的待验证条件；实现任务不能借文档通过掩盖其自身要求的测试未执行。

## 独立性的判定

审查者未编写、未修改被审产物。审查者阅读上下文和研究证据不影响独立性。原作者即使切换角色也不算独立。一个审查代理可以审查明确分开的多个任务，但每个任务必须有自己的范围、证据和结论。

审查代理发现问题后只报告，不直接编辑；否则不能继续作为其修改范围的独立审查者。对执行者完成的修复进行只读复审仍然符合独立性。

## 审查范围

文档审查：事实与来源、已验证/建议/未知的区分、约束一致性、任务依赖、可执行步骤、验收证据和本地资源。

实现审查：正确性、生命周期、权限、展示资源与契约、超时恢复、输出模式、认证提示、隐私以及与现有桌面行为的兼容。

验收审查：测试环境和版本、证据与结论匹配、故障恢复、未测项，尤其检查是否将请求确认或帧提交误当屏幕呈现。

审查不扩大当前任务授权，不安装、部署、切换显示管理器或改变会话来补证据。

## 优先级与关闭

| 优先级 | 含义 | 完成门槛 |
| --- | --- | --- |
| P0 | 凭据泄漏、认证绕过或灾难性破坏 | 立即处理，修复并复审 |
| P1 | 登录不可用、无法恢复、生命周期严重错误 | 修复并复审 |
| P2 | 功能、契约、关键事实或验收有实质缺陷 | 修复并复审 |
| P3 | 不阻断目标的改进 | 记录处置，审查确认可后续处理 |

有分歧时先核验事实，不凭执行者单方面降级绕过审查。独立审查“未发现问题”不等于证明不存在缺陷，也不等于未执行的硬件测试通过。

## 记录与状态

状态：待开始 → 执行中 → 待独立审查 → 修复中 → 待复审 → 完成。未测或依赖缺失可标“阻断”，并写明原因。

每次记录至少包含任务 ID、执行者、独立审查代理 ID、审查日期、被审范围、版本/摘要、问题与优先级、执行者修复、检查结果、复审版本、关闭结论和未测限制。记录保存在本地忽略目录 `.build/greeter-review/`，不上传过程材料。

审查结果保存于本地忽略目录 `.build/greeter-review/`。结论只对被审版本有效，后续变更再次审查。本规则不要求对审查行为递归派发审查代理；新增实现或实质文档修改仍需进入上述流程。
