# 安装后只剩壁纸：共享 QML 模块缺失

若注销或重启后没有顶栏、Dock、桌面图标，应先检查
`journalctl --user -u kos-shell.service -b`。出现 `module "../shared/qml/i18n" is not installed`
等错误时，Shell 未能加载。`org.kos.desktop` 只负责壁纸，其他桌面界面由
Quickshell 提供，因此该故障会让整个桌面界面不可用。

源码经解压、同步或跨系统复制时，`shell/shared/qml` 和 `shell/Kos/Ui` 下的符号链接
可能变为空目录、普通文本文件或失效链接。旧安装器只补齐部分目录，可能报告安装成功，
直到重登录才暴露问题。正常 Git checkout 不一定触发此问题。

更新后的 `kosctl install` 从规范的 `shared/qml` 内容生成这两套模块目录，不再依赖
源码别名是否仍是符号链接。部署前检查模块声明及共享 QML 的相对导入，缺失时在旧运行
目录被清理之前失败。生成的 Shell 目录也会暂存并检查，检查通过后才替换部署目标。
部署失败不会继续接管 Plasma 桌面或打印安装成功摘要。

已受影响的安装需要使用完整、更新后的源码重新安装；仅更新仓库不会自动修复已有安装。
若提示规范共享目录缺文件，应恢复完整源码或重新获取发布包后重试，不要只创建空目录。
诊断日志可区分共享模块缺失与其他 Shell 加载错误；这一修复不保证所有“只剩壁纸”问题
都有相同原因。

CI 的 `Test Shell QML deployment with damaged source aliases` 使用临时目录覆盖正常链接、
空目录、普通文本、失效链接、缺失别名和只读输入，并检查内容缺失时的失败及桌面接管阻断。
它不启动 Shell、不修改真实安装。图形登录验收仍应在专用虚拟机执行。
