# 安装后只剩壁纸：共享 QML 模块缺失

若注销或重启后没有顶栏、Dock、桌面图标，应先检查
`journalctl --user -u kos-shell.service -b`。出现 `module "../shared/qml/i18n" is not installed`
等错误时，Shell 未能加载。`org.kos.desktop` 只负责壁纸，其他桌面界面由
Quickshell 提供，因此该故障会让整个桌面界面不可用。

源码经解压、同步或跨系统复制时，`shell/shared/qml` 和 `shell/Kos/Ui` 下的符号链接
可能变为空目录、普通文本文件或失效链接。旧安装器只补齐部分目录，可能报告安装成功，
直到重登录才暴露问题。正常 Git checkout 不一定触发此问题。

更新后的 `kosctl install` 从规范的 `shared/qml` 内容生成这两套模块目录，不再依赖
源码别名是否仍是符号链接。部署前检查模块声明及共享 QML 的相对导入，缺失时在旧运行
目录被清理之前失败。生成的 Shell 目录也会暂存并检查，检查通过后才替换部署目标。
部署失败不会继续接管 Plasma 桌面或打印安装成功摘要。

已受影响的安装需要使用完整、更新后的源码重新安装；仅更新仓库不会自动修复已有安装。
若提示规范共享目录缺文件，应恢复完整源码或重新获取发布包后重试，不要只创建空目录。
诊断日志可区分共享模块缺失与其他 Shell 加载错误；这一修复不保证所有“只剩壁纸”问题
都有相同原因。

CI 的 `Test Shell QML deployment with damaged source aliases` 使用临时目录覆盖正常链接、
空目录、普通文本、失效链接、缺失别名和只读输入，并检查内容缺失时的失败及桌面接管阻断。
上述文件用例不启动 Shell、不修改真实安装。

CI 另外必跑 `kos-shell.installed-startup`：通过正式部署工具处理正常链接、空目录、
链接文本和失效链接，删除临时输入源码，再在隔离的 KWin 会话启动安装后的完整 Shell。
每种情况必须出现 `Configuration Loaded` 并持续存活；删除已安装的翻译目录文件时，
真实 QML 引擎必须拒绝加载。CI 清单会阻止该测试缺失、被跳过或没有报告却显示通过。
这覆盖模块加载，不代表真实登录、平台连接、用户配置或桌面交互都已验收。

专用虚拟机中的完整登录验收流程：

1. 备份用户运行目录、配置和服务，记录源码提交及构建参数；使用该提交构建并安装。
2. 在 VM 内执行 `python3 tests/shell-startup/login-vm.py --output /tmp/kos-before.json`。
   探针要求真实 Wayland 登录、三个服务存活、平台与数据连接正常、桌面文件服务就绪，
   Dock 及当前布局需要的顶栏窗口可见，并持续观察 30 秒，期间 PID/重启计数不能变化。
3. 在 VM 中注销并重新登录，再执行
   `python3 tests/shell-startup/login-vm.py --after /tmp/kos-before.json --output /tmp/kos-after.json`。
   必须产生新登录会话，且再次满足上述条件。探针自身不注销用户，也不会在物理主机执行。
4. 保存本轮服务日志与桌面截图，实际检查顶栏、Dock、桌面图标和应用启动。
   窗口的 `visible` 属性不能替代最终画面和点击交互验收。

缺少构建依赖、安装未完成、未实际重新登录或未完成交互检查时，应分别标为未验收，
不能以隔离启动通过替代完整登录验收。
